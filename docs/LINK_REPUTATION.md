# Message checks and optional link reports

Guardian can assess the request in a message without connected records. A local text check looks for actions such as giving a caller a one-time code, changing an invoice account, allowing a remote support session, or paying a relative who claims to have a new number. It also inspects the written address for mismatched link text, a disguised host or a shortened link. A warning or an educational example is different from a demand. If the private analysis service is unavailable, the saved check remains unassessed and is not charged as a completed AI assessment. Saving a draft or reaching an allowance limit does not grant an assessment.

The saved-case model receives the original evidence alongside these observations. Suggestions about uploaded screenshots are conditional on the recognised or QR text selected by the customer. Neither an image, a matching record, a brand name nor a reputation result authenticates a sender. Missed signals are possible. HMRC, for example, does send some genuine texts with links and some refund confirmations; a request for personal or financial details by text is the relevant warning. The [HMRC guidance](https://www.gov.uk/guidance/check-if-a-text-message-youve-received-from-hmrc-is-genuine) lists the distinctions. Other fixed sources are [Report Fraud’s payment diversion guidance](https://www.reportfraud.police.uk/mandate-fraud), and the FTC’s [tech support](https://consumer.ftc.gov/features/pass-it-on/impersonator-scams/tech-support-scams) and [family emergency](https://consumer.ftc.gov/consumer-alerts/2018/07/scammers-create-fake-emergencies-get-your-money) guidance. Guidance checks request only a fixed official URL. A checked date appears only after the expected guidance text has been found.

## Which API to connect

Keep the existing Meta model connection. Saved checks use the private assessment route. Initial contradictory identity evidence can select the configured Wonder model; a simple follow-up returns to Spark. The separate lookups below supply threat evidence. In Community mode, Google Web Risk is the baseline check and VirusTotal supplies an additional existing report when its allowance permits. Findings are retained separately; a result with no warnings from one provider cannot cancel a warning from the other.

**Google Web Risk Lookup.** Enable `webrisk.googleapis.com` for the intended Google Cloud project, configure billing/quota as required, and create an API key restricted to Web Risk. Store the key as the server secret `GUARDIAN_GOOGLE_WEB_RISK_API_KEY`. Select `GUARDIAN_LINK_REPUTATION=google-web-risk` for Google alone, or configure Community mode below to supplement Google with VirusTotal. Redeploy the saved version to apply environment changes. Do not place the key in source, screenshots, browser code or chat. Without the Google secret, no Google request is made; Community mode records that missing coverage, and another provider's result must not be labelled a Google check. Disable lookups by clearing the selection; revoke keys separately if needed.

The Worker calls only [`uris.search`](https://docs.cloud.google.com/web-risk/docs/reference/rest/v1/uris/search). It sends the exact eligible URL, including its permitted path, with the key in a header. It sends no account ID, message or document to Google. At most one URL per signed-in assessment turn is checked for malware, social engineering and unwanted software. The deadline is 1.8 seconds and the response limit is 32 KiB. There are no retries, redirects, submissions, rescans or visits to the suspect site. The Update, Evaluate and Submission APIs are not used.

Eligible sources are the current message and, on the first turn, selected screenshot/QR text or an explicitly imported original email. When a button target is present, the lookup considers its destination rather than its printed label. Retrieved private history, connected-mailbox search results and statement records do not trigger reputation requests. Eligibility is deliberately narrow: HTTP(S) only, common public domains and simple public paths. Signed/reset links, private paths, query strings, fragments, credentials, IPs, tenant subdomains and unusual addresses are skipped, not shortened into a different URL. No match, missing key, stale response or lookup failure is ever evidence of safety. Findings include the provider and time; Google warnings include an accuracy advisory. Google's saved results are historical after their expiry, capped by Guardian at 30 minutes; VirusTotal records preserve the existing report's analysis date.

**Activation check.** With the restricted secret installed, make one signed-in synthetic check using `https://example.com/`. Open **See what I checked** and confirm a dated Google result, not “not checked” or “unavailable”. For a positive provider test, use the official test URI from [Google’s Lookup guide](https://docs.cloud.google.com/web-risk/docs/lookup-api) against the lookup endpoint in a controlled operator test; this special test path is deliberately outside Guardian’s customer URL policy. Never open a threat URL to test the lookup. Review [Web Risk pricing](https://cloud.google.com/web-risk/pricing) and set provider quotas for the project.

## Official identity comparisons

`web/assets/organisation-directory.js` contains fixed official sources for HMRC and its eight named debt collectors (catalogue reviewed 4 November 2026). The worker rechecks the relevant contact pages and the current section of [HMRC’s list](https://www.gov.uk/guidance/what-will-happen-if-you-do-not-pay-your-tax-bill), excluding the update history. For a named agency it distinguishes being listed from a particular debt, caller or sender being genuine. Contact details are allowlisted and then compared against the reviewed page. A complaints number is labelled as such; unrelated third-party contact details on the same page cannot become agency contacts. A failed fetch is shown as unverified. A warm worker may reuse official reference facts for up to six hours; these facts contain no message or customer identifier. At most three recognised organisations are consulted per check.

Compare full From, Reply-To, email-button targets, visible and embedded web destinations and telephone-button targets. A known domain is separate from a published exact mailbox. UK domestic and international phone formats are normalised. A phone match is not proof of caller identity. Original EML/MBOX and selected Gmail records preserve HTML link evidence even when a plain-text alternative exists. Outlook search still supplies a preview; a screenshot or preview cannot expose a hidden destination. Uploaded or pasted authentication headers cannot establish trusted receiver provenance. There is no unrestricted organisation search or automatic sender authentication. A conclusive mismatch may ground a caution even if the model overlooks it. Missing information alone is not a fraud verdict.

## VirusTotal Community mode

Select `GUARDIAN_LINK_REPUTATION=virustotal-community` and store both the Google key above and the Community key, `GUARDIAN_VIRUSTOTAL_COMMUNITY_KEY`, as protected server secrets. The existing selector enables Google as the baseline plus VirusTotal as supplementary evidence; no new key type or AI connection is required. This mode was requested by the operator for the current community project. It does not assert that VirusTotal has approved the project's classification; its Public API terms remain applicable, including the restrictions on commercial products and business workflows.

The adapter reads an existing report for one eligible public URL fingerprint. It never submits a URL or file for scanning. A durable, site-wide admission check uses the existing rate-limit table: at most four reservations in a conservative 68-second window and 500 per UTC day. The margin covers bounded preflight and transport delay; a delayed admission is not sent, and the final eight seconds before UTC midnight admit no new lookup. The daily ceiling also keeps calendar-month use within the account's displayed 15,500 maximum. Other use of the same API key outside Guardian can still consume its upstream allowance.

Google is checked for the same eligible URL even when VirusTotal supplies a current report. The lookups start in parallel: Google has a 1.8-second request deadline and 32 KiB response limit; VirusTotal has a 1.8-second request deadline and 512 KiB limit after its bounded quota preflight. Each provider's finding, time and any missing coverage appear separately under **See what I checked**. A missing credential, quota refusal, absent or stale report, or failed provider does not suppress the other result. A warning from either provider grounds a caution; a result with no warnings is not proof of safety and never cancels the other's warning. Private/unusual URLs go to neither provider and consume no Community allowance.

The community and commercial keys are deliberately separate. Changing the selector to `virustotal-commercial` requires its own credential and permitted licence scope; introducing a paid plan must not silently reuse a Community key.

## Optional alternative: commercially licensed VirusTotal

The integration fetches **existing VirusTotal URL reports**, not a new scan. Keep both settings absent unless the operator has a licence permitting a commercial customer-facing product to use and display these report summaries. The [public API](https://docs.virustotal.com/docs/difference-public-private) is non-commercial. Confirm contract scope, quota and permitted display/retention before enabling; a key alone is not evidence of a licence. No credential, paid plan or external account is provisioned by this change.

1. Obtain suitable commercial access. Store its key in the Worker’s server-only secret `GUARDIAN_VIRUSTOTAL_COMMERCIAL_KEY`. Set `GUARDIAN_LINK_REPUTATION=virustotal-commercial` in the same environment. The secret must never be added to source, the client, a browser test or the submission archive.
2. In staging, use a dedicated signed-in test account, a public non-private URL with an already-known report that the licensee is permitted to access, and a model configured in private mode. Verify the host and original report date against the provider’s interface. Separately confirm that a private link is skipped, an unknown digest is not submitted and an unavailable provider leaves the AI assessment workable. Do not open a suspect destination to test this integration.
3. Review quotas with the provider. There is at most one report request per signed-in assessment turn, subject to the product’s existing rate limits. An external report call has a 1.8 second deadline, a 512 KiB response limit and no retry or redirects. Disable by removing the operator setting. To revoke access, also revoke or remove its secret.

The Worker calls only [`GET /api/v3/urls/{id}`](https://docs.virustotal.com/reference/url-info). The [identifier](https://docs.virustotal.com/reference/url) is the SHA-256 digest of an eligible canonical URL, **never** the reversible base64 URL form. The provider may recognise a digest it already knows or guess a common public URL; it is pseudonymous, not anonymous. The customer’s original text, query, account ID, filenames, mailbox records and documents do not go to VirusTotal. Only the first eligible URL in the current message or, on the initial turn, selected QR/OCR or original email evidence is considered. No lookup is performed in the browser, public chat, guest assessment or on search results from an attached account. Signed-in message assessments can use the same service. A neutral or missing report never clears a payment or authenticates anyone.

To avoid private tokens and canonicalization ambiguity, the supported subset is narrow: explicit HTTP(S) on a conservative list of public suffixes, simple DNS names (optional `www`), a root or a small set of common static paths (for example `/login`), and no credentials, queries, fragments, ports or unusual path syntax. Skips are explicit. The code does not submit or re-scan a URL, follow redirects, resolve the host, or fetch the suspect site. It rejects a response whose object ID or URL does not match. Only validated counts and the prior analysis date are summarised; the full provider response is not persisted or sent to the model. Reports older than seven days are labelled stale. `404`, unavailable and zero flags remain distinct outcomes. Historical results describe what was checked at that time.

## Version 79 validation, 4 November 2026

The version 79 evaluator exercised 43 deliberately constructed phrases: 19 action requests or reports of action, 21 legitimate or educational examples, and 3 ambiguous messages. The local observations matched the listed expectations on 19/19, 21/21 and 3/3 respectively. For a local baseline, the same 43 fixtures were also run against the previous repository version (`0b3b8ed`). Its rules matched 4 of the 19 expected action topics and 21 of the 24 expected no-signal cases; the revised rules matched 19 and 24 respectively. These deliberately targeted cases measure the rule changes, not performance against another provider. A zero-signal expectation means “no listed clue”, not “safe”. The 16 existing evidence fixtures pass structural validation with `node scripts/evaluate-context.mjs`.

The report-boundary and saved-check tests use transport doubles, an in-memory database, hostile/missing/stale responses, and a model that attempts to clear a flagged link. They establish route behaviour, not real provider accuracy or availability. No licensed VirusTotal key or private inference key was available in the local environment. This does **not** measure detection on unseen fraud, model quality, parity with commercial checkers, or a live integration. With a legitimate private provider configuration and a budget, the same authored set can be run via `node scripts/evaluate-message-first.mjs --live 43`. It uses isolated synthetic cases; review the answers and their exact actions, not just their status labels. Benchmark against independent held-out cases and a licensed comparator before advertising product parity.

## Message-language regression expansion

The local phrase corpus now contains 116 examples. The separate message-variants suite challenges the rules with paired demands and counterexamples, alternative sentence orders, screenshot text, competing generated advice, emphasis, capitalisation, OCR line breaks and mobile spacing. These are tests of local observations and the assessment boundary. A missing observation does not establish safety. The private model still evaluates the supplied request, and the optional external URL-report lookup has separate activation requirements.

On the same expanded fixtures, version 79 picked up the expected action in 22 of 56 actionable examples and produced an unexpected signal on four of the 60 benign or inconclusive examples. The updated rules picked up 56 of 56 with zero unexpected signals on those 60. These examples include development regressions and are not a population-level detection rate. Live-provider accuracy and adversarial scope-classification accuracy were not measured.
